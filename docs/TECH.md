# SetLoop — техническое решение

Продуктовые решения — в [SPEC.md](SPEC.md), дизайн — в [DESIGN.md](DESIGN.md).

## Окружение

- Xcode 16.3 / Swift 6.1 на машине разработки (2026-10-14).
- К релизу проверить требование App Store к версии SDK/Xcode — вероятно, нужно обновиться до Xcode 26.

## Решения

### T1. UI и хранение — SwiftUI + SwiftData

- Интерфейс полностью на SwiftUI, минимальная версия iOS 17.
- Хранение — SwiftData. Модель сразу совместима с CloudKit (синхронизация в v1.1): у всех свойств есть значения по умолчанию или они опциональны, без `@Attribute(.unique)`, все связи опциональны.
- Каждое изменение (создание, правка, порядок, удаление) сразу сохраняется через `context.save()`. На автосохранение не полагаемся: если приложение выгрузят до него, изменение теряется.
- Движок таймера не зависит от хранилища: на вход получает готовый плоский план шагов (value types), поэтому его можно тестировать и переиспользовать отдельно.

### T2. Фон и экран блокировки — фоновое аудио + расчёт от реального времени

- Background mode `audio`: на время тренировки активна аудиосессия (`.playback`, `.duckOthers`, с учётом «Игнорировать бесшумный»); сигналы и голос играются в момент смены шага; приложение живо и само обновляет Live Activity и обрабатывает её кнопки.
- Состояние таймера — не счётчик тиков, а отметки времени (старт шага, накопленная пауза). Текущий шаг и остаток всегда вычисляются из `now`, поэтому после заморозки/прерывания приложение мгновенно показывает верное состояние.
- Live Activity показывает обратный отсчёт системно (`Text(timerInterval:)`/`ProgressView(timerInterval:)`) — цифры идут даже без приложения.
- Прерывания аудиосессии (звонок, Siri) обрабатываются: пауза при звонке по D6, восстановление сессии после.
- Если все звуки и голос выключены, тишину «вхолостую» не играем (риск App Review 2.5.4). Следствие: в фоне iOS заморозит приложение, текущий шаг на Live Activity досчитает, но смена шагов, вибрация и обновление Live Activity произойдут только при возврате в приложение. В настройках — пояснение под переключателями звука.

### T3. Структура проекта — приложение + Widget Extension + локальный пакет `SetLoopCore`

- `SetLoopCore` (локальный Swift Package): план тренировки (value types), движок таймера, атрибуты Live Activity (`ActivityAttributes`), типы шагов и палитра. Без SwiftData/UIKit/SwiftUI-экранов. Тесты — `swift test` на Mac. ActivityKit есть только в iOS, поэтому код с `ActivityAttributes` обёрнут в `#if canImport(ActivityKit)`.
- Приложение `SetLoop`: модели SwiftData, экраны, аудио/голос, App Intents, управление Live Activity.
- `SetLoopWidgets` (Widget Extension): Live Activity и Dynamic Island; зависит от `SetLoopCore`.
- Сторонних зависимостей нет.

### T4. Состояние и логика — «чистый SwiftUI» + точечные контроллеры

- Экраны читают данные через `@Query` и правят модели напрямую; `@Observable` вместо `ObservableObject`.
- `WorkoutController` (`@MainActor`, `@Observable`, один экземпляр): связывает движок, аудио/голос, вибрацию, Live Activity, прерывания (звонки) и App Intents.
- Отдельные модели логики только там, где она нетривиальна: редактор таймера (лимиты, «объединить в блок»), сохранение тренировки в историю.
- Без TCA и сторонних архитектурных библиотек.
- Настройки (SPEC D22) — `AppSettings` (`@Observable`, в окружении), хранятся в `UserDefaults`; цвета типов — JSON `StepColors`. `WorkoutController` читает настройки при старте тренировки.

### T5. Модель данных — таймер и тренировка как одна запись со снимком структуры

- `SavedTimer` (SwiftData): поля для списка — `id`, `name`, `sortIndex`, `createdAt`, `updatedAt`, `totalDuration` (кеш) + `definitionData: Data` — JSON `TimerDefinition` из `SetLoopCore`.
- `TimerDefinition` (Codable, value type): `version`, подготовка, сеты, отдых между сетами, блоки → шаги, заминка, «Пропускать последний отдых». Порядок — порядок массивов.
- Редактор работает с копией `TimerDefinition`; запись в базу только по «Готово», «Отмена» ничего не трогает.
- `WorkoutRecord` (SwiftData): `id`, `startedAt`, `name`, `note`, `duration`, `status` (полностью/частично), `workTime`, `restTime`, `otherTime`, `completedSteps`, `totalSteps` + `stepsData: Data` — снимок пройденных шагов с отметками выполнено/пропущено. Плюс `definitionData: Data` — снимок `TimerDefinition` для «Повторить». Независим от таймера: правка или удаление таймера историю не меняют.
- CloudKit (v1.1): таймер синхронизируется целиком, конфликт — побеждает последняя правка; запись не «рвётся».
- Миграции формата — по полю `version` при декодировании.

### T6. Звуки — свои синтезированные, голос — системный TTS

- Сигналы синтезируются в коде (`SoundSynth` в `SetLoopCore`) при первом использовании, без файлов в ресурсах. Лицензионных вопросов нет, громкость выровнена (пик 0.8). В настройках есть вариант «Выкл».
- Наборы в духе системных звуков iOS (мягкая атака, затухание, 440–880 Гц, лёгкая реверберация): «Стекло», «Маримба», «Нота». Выбраны на слух 2026-10-14 на странице-лаборатории https://claude.ai/artifact/6QzA8c4yAykNzW7yW9q3ae, алгоритм страницы и `SoundSynth` совпадают. Тик отсчёта у каждого набора свой. Всё опущено на 3 полутона от значений страницы (ползунок «Высота» = −3), затухание всех сигналов — 0.3 от страницы.
- В каждом наборе: тик отсчёта за 3 с, длинный сигнал смены шага с вариантом по типу шага (работа / отдых / подготовка-заминка), финальный сигнал конца тренировки.
- Воспроизведение — `AVAudioPlayer`/`AVAudioEngine` в общей аудиосессии T2 (ducking).
- Голос — `AVSpeechSynthesizer`, язык интерфейса (RU/EN), офлайн: название шага при старте и «3-2-1» (по D5).
- При включённом голосе отсчёт «3-2-1» произносится вместо тиков; название шага звучит после сигнала смены шага.
- Приглушение музыки: на время сигнала сессия перезапускается с `.duckOthers`, музыка возвращается через секунду тишины после последнего сигнала или фразы.
- «Игнорировать бесшумный» выкл → категория `.ambient`: iOS глушит её и на заблокированном экране, поэтому в фоне сигналов нет. Пояснение под переключателем.
- Вибрация — системные звуки: короткий тап на отсчёте, стандартная вибрация на смене шага.
- Готовые CC0-звуки (Kenney Interface Sounds) прослушаны и отклонены 2026-10-14.

### T7. Идентификаторы и репозиторий

- Репозиторий: https://github.com/PersonaN1/SetLoop (публичный, ветка `main`; переименован из `Timer` 2026-10-14). Корень репозитория — папка `SetLoop/`.
- Bundle ID приложения: `io.github.personan1.setloop`; расширение: `io.github.personan1.setloop.widgets`. Нижний регистр — Bundle ID чувствителен к регистру, единый стиль исключает путаницу.
- App Group в v1 не нужен (Live Activity получает данные через `ActivityKit`); добавим `group.io.github.personan1.setloop` в v1.1 вместе с виджетом.
- Страницы для App Store (D20): GitHub Pages из папки `site/` через GitHub Actions → `https://personan1.github.io/SetLoop/privacy/` и `/support/`.
- Поддержка — GitHub Issues этого репозитория.

### T8. Сборка и язык

- Swift 6, режим строгой проверки конкурентности; минимальная iOS 17.0, только iPhone; ориентации — портрет и ландшафт.
- Проект описан в `project.yml` (XcodeGen — инструмент разработки, не зависимость приложения); сгенерированный `.xcodeproj` тоже коммитится, чтобы проект открывался без установки XcodeGen. Папки подключены как синхронизируемые группы — новые файлы не требуют правки проекта.
- Версии: `MARKETING_VERSION` 1.0, `CURRENT_PROJECT_VERSION` растёт с каждой сборкой для App Store Connect.

### T9. Движок таймера

- Чистая функция в `SetLoopCore`: `TimerDefinition` → плоский план шагов (с учётом сетов, повторов блоков, «Пропускать последний отдых»); `state(at:)` → текущий шаг, остаток, позиция (сет/цикл), следующий шаг.
- Время — монотонные часы (`ContinuousClock`) для логики; для Live Activity переводится в `Date`.
- Контроллер не тикает каждые 0,1 с, а планирует следующее событие (тик отсчёта 3-2-1, смена шага, конец) и спит до него; звук и вибрация запускаются по событию.
- Экран тренировки обновляется через `TimelineView` только пока он виден.
- «Пропускать последний отдых»: убирается отдых, которым заканчивается последний сет; если есть заминка, она остаётся и идёт сразу после работы.
- Досрочное завершение: текущий шаг попадает в журнал с отметкой «прерван» (`interrupted`), шаги после него не сохраняются.
- Команды: пауза/продолжить, пропустить, назад (<2 с от начала шага — предыдущий шаг, иначе в начало текущего), завершить. Журнал фактически пройденных шагов (выполнен/пропущен) копится по ходу и идёт в `WorkoutRecord`.

### T10. Live Activity и Dynamic Island

- Старт при начале тренировки (если включено «Показывать на экране блокировки»), обновление на каждой смене шага и паузе, завершение по концу тренировки с политикой скрытия «через несколько минут».
- `ContentState`: тип шага (цвет), название, `endDate` или «пауза + остаток», сет/цикл, следующий шаг. Обновления локальные, без push и сервера.
- Кнопки «Пауза/Продолжить» и «Пропустить» — `LiveActivityIntent`, выполняются в процессе приложения и вызывают `WorkoutController`.

### T11. Системные интеграции

- Звонки (D6): уведомления о прерывании `AVAudioSession`; аудиосессия активна всю тренировку на переднем плане. CallKit не используем (ограничения App Store в Китае).
- «Не гасить экран»: `isIdleTimerDisabled` только во время тренировки.
- App Shortcuts (D15): «Запустить таймер <название>» (`AppEntity` для `SavedTimer`), «Пауза», «Продолжить»; доступны в Siri, Spotlight и на кнопке действия.
- Локализация: String Catalog (`.xcstrings`), исходный язык — английский, перевод — русский; множественные формы через правила каталога.
- Доступность: Dynamic Type (text styles), подписи VoiceOver, учёт «Уменьшить движение».

### T12. Качество и выпуск

- Тесты: Swift Testing; основной объём — движок и построение плана в `SetLoopCore` (`swift test`), плюс сохранение в историю; один UI smoke-тест на запуск таймера.
- CI: GitHub Actions на macOS-раннере (бесплатно для публичного репозитория) — `swift test` пакета и сборка приложения на каждый push/PR в `main`.
- Без аналитики и SDK отчётов о сбоях (Data Not Collected); логи — `os.Logger`; сбои — через Xcode Organizer от пользователей, согласившихся делиться данными.
- Сборка для App Store — архив из Xcode и загрузка в App Store Connect вручную; автоматизацию (fastlane/Xcode Cloud) — по необходимости позже.
